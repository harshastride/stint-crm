# Security audit, October 2026

Scope: database functions, `app/api/**`, search/filter code, PDFs, secrets. Fixes are in migration `20261004000059_security_fixes.sql`, `lib/pgrst.ts`, `lib/server/guard.ts` and the API routes. Checks are in `scripts/test-security.mjs` under "Injection & API hardening".

| # | Severity | Where | Problem | Fix |
|---|---|---|---|---|
| 1 | Critical | `lead_brief`, `candidate_brief` (DB) | Any caller, even signed out, got a lead's full mobile and email with no checks or log | Service role only (059) |
| 2 | High | All SECURITY DEFINER functions | Signed-out users (anon) could run 70+ of them | EXECUTE taken from anon/PUBLIC; signed-in users get only an allow-list; default privileges changed for new functions |
| 3 | High | `emit_event`, `next_receipt`, `pick_assignee`, `staff_can_page` | Staff could forge webhook events, burn receipt numbers, read others' permissions | Service role only |
| 4 | Medium | `components/CommandMenu.tsx` | Search text went into a PostgREST `or=` filter; quotes, dots, `*` were not escaped | `lib/pgrst.ts` quotes every value (`ilikeHas`, `pgQuote`) |
| 5 | Low | `FilterBuilder.tsx`, `Fields.tsx`, `api/integrations/lead` | Own quoting copy; `%`/`_` acted as wildcards in exact-name lookups | Shared helper; `likeExact` |
| 6 | Medium | `api/admin/reset-password` | Could reset a student login, or an Admin's password without being Admin | Target must be staff; Admin targets need Admin |
| 7 | Medium | `api/admin/invite` | Non-admin with Users page could create an Admin login | Admin role needs Admin; input checked |
| 8 | Medium | `api/pdf/quote` | Admin PDF showed full contact without the reveal log (rule 11) | Logged in `data_access_log` |
| 9 | Medium | `api/integrations/hooks` | Webhook target could be cloud metadata / link-local address (SSRF) | `badTarget()` blocks them and URLs with passwords |
| 10 | Low | Cookie POST routes (admin, portal invite, recordings process, voice) | No Origin check (SameSite=Lax already helps) | `crossSite()` refuses other origins (403) |
| 11 | Low | Most API routes | Raw database/storage error text sent to caller | `fail()` logs a code, returns a plain message |
| 12 | Low | Secret compares | `timingSafeEqual` on strings could throw on multi-byte keys | `safeEqual()` hashes first |
| 13 | Low | PDF and notes routes | Ids not checked as UUIDs; filename not sanitised | `isUuid`, `safeFilename`, `nosniff`, `no-store` |
| 14 | Low | `api/recordings/upload` | Any content type, free-form extension and date | Audio types only, fixed extension list, date parsed |
| 15 | Low | `api/mobile/login`, `refresh` | No rate limit | 10 / 30 per minute per IP (in memory) |
| 16 | Low | `.gitignore` | `.env` / `.env.production` not ignored | Added `.env`, `.env.*` (keeps `.env.example`) |

Checked and fine: no `dangerouslySetInnerHTML`; no `?next=` redirects; PDFs use pdf-lib (no HTML); dynamic SQL (`run_report`, `merge_people`, `candidate_private_set`, `portal_save`, `log_status_change`) uses `%I`/`%L` and whitelists; every definer function sets `search_path`; no keys or personal data in logs.

Not done: webhook replay protection for incoming calls (they use an API key, not signatures); rate limits are per server process.
